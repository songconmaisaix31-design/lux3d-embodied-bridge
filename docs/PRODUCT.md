# 产品目标

> 一句话：**生成模型负责让资产好看，这个产品负责让资产的每一次实验都能被第三方复核。**

---

## 1. 我们要解决的那道缝

3D 生成已经跨过了「像不像」的门槛，具身仿真也已经跨过了「跑不跑得动」的门槛。但两者之间
没人负责一件事：**这个实验结论，属于哪一次生成？**

它具体表现为三个正在发生的浪费：

1. **重生成即失忆**。prompt 微调一次，网格变了、凸包变了、抓取成功率也变了，上一轮结论作废，
   但没人知道是哪一步作废的。
2. **成功率无法溯源**。一份「抓取成功率 73%」的训练报告，说不清用的是哪一版资产；换机器复跑
   对不上，只能归因于「仿真随机」。
3. **演示与工程脱节**。Demo 里的模型很漂亮，但复现它需要一套只有作者本机才有的环境。

缝的名字叫**身份**。

---

## 2. 产品是什么

一条把「生成」和「实验」焊死的桥，三件东西：

```
一句 prompt / 一张图
      │  Aholo Lux3D（G1-Turbo，GLB）
      ▼
  资产文件 ── sha256 + 三角数 + 包围盒 ──▶ assets.lock.json（asset_id）
      │  转 STL（引擎唯一全量解析的格式）
      ▼
  URDF 的 <collision> ── 资产 id 写进描述文件 ──▶ spec_hash
      │  引擎 embodied_sim_collect
      ▼
  每集逐位指纹 ── 双跑一致 ──▶ 回执（可提交、可审计、可发红）
```

**它卖的不是模型，是账本。** 模型是上游的；本产品补的是「谁为哪份资产、在什么规格下、
产出了什么结果」这一层记账，以及记账可验证的能力。

---

## 3. 三个可验证事实（这是产品的全部说服力）

| 事实 | 证据（2026-11-19 实测） |
|---|---|
| 同一份产物 → 同一个 id | 同一 GLB 在 Linux 与 Windows 上各自入账，均得 `asset 6e593a666736fce0`，源 sha256 相同 |
| 同一份 spec → 同一串指纹 | `spec_hash b84b3add08d4a9c3`，两机 `fingerprints.v2.json` **全量逐位 MATCH**（1400 transitions） |
| 改一位 → 立刻发红 | 把 `episode_fingerprints_v2[0]` +1，`verify` 精确报出 `$.fingerprints.episode_fingerprints_v2[0]: …287 vs …288` |

第三条是全产品的价值观：**不一致从不悄悄兜底**。宁可红得难看，也不给出「大概是对的」结论。

---

## 4. 谁会用，为什么

| 角色 | 现在的痛点 | 用了之后 |
|---|---|---|
| 具身智能 / VLA 团队 | 训练集里的资产来路不明，换一版数据没法归因 | 每个 episode 带资产 id 与 spec 指纹，数据集可审计 |
| 仿真评测 / 第三方复现 | 「我复现不出来」，说不清差在哪 | 一行 `verify` 给出第一处分歧路径 |
| 3D 内容生产者 | 生成的模型只能看，进不了下游管线 | GLB → STL → URDF 一条命令，尺寸/面数/单位透明 |
| 比赛与论文评审 | 截图无法证明真的跑过 | 回执 + 相机帧 + 日志三件套，任何人可重跑 |

---

## 5. 明确不做什么

- **物理仿真**由外部 `lux3D-engine` 运行。工作台负责将生成资产接入仿真场景。
- **不做 3D 生成模型本身**。LX3D 是上游能力，我们只把它的产物变成可计算的输入。
- **不承诺成功率**。桌面 2 自由度臂抓不到方块就是抓不到，如实报 0%。产品的 KPI 是「回执一致率」，
  不是「成功率好看」。
- **不做云端托管平台**（至少现在不）。先证明这条缝重要且可验证，再谈服务化。

---

## 6. 怎么算成了（度量）

| 指标 | 现在的值 | 目标 |
|---|---|---|
| 同一资产的 `asset_id` 跨机器一致率 | 2/2 | 100%，且写进 CI |
| 同 spec 回执跨机器逐位一致率 | 1/1（Linux ↔ Windows） | 每版本回归 |
| 从 prompt 到可跑 URDF 的人工步骤 | 0（一条命令） | 保持 0 |
| 从「分歧」到「定位到字段」的时间 | 秒级 | 保持秒级 |
| 首次接入者的上手时间 | 未测 | < 10 分钟（文档 §1 已压到 3 条命令） |

## 7. 路线图

**M0 — 已交付（2026-11-19）**
零依赖 Python 桥（45 条单测 / 三平台 CI）、真实 Lux3D 跑通、真实引擎回执、Linux↔Windows 逐位一致、
8 张终端实物帧 + 1400 张相机帧 + 90 秒分镜。

**M1 — 让身份进入实验身份本身**
把 `asset_id` 折进 `spec_hash` 的显式字段，而不是停留在注释里；这样「换资产」在指纹层面直接可见，
不必靠人去比对两棵树。同时补一条负向测试：换资产 → 指纹必变。

**M2 — 多资产与批量**
一次生成多个物件、一个场景多资产组合（料箱 + 抽屉 + 台面），`assets.lock.json` 升为场景级清单，
`verify` 支持按资产过滤。

**M3 — 接上「看」的那一半**
把 3DGS / LuxReal 的产物接进 Viewer，做「同一次重建，既看又算」的对照：视觉资产与碰撞资产同源，
但明确标注二者不是同一份几何。

## 8. 已知风险与反驳

| 风险 | 我们的回答 |
|---|---|
| 「这不就是算个哈希？」 | 哈希谁都会算。难的是让上游引擎真的吃下这份资产：GLB 只有探针、STL 才是全量凸包，单位/朝向/`home` 全零每个坑都会让「看起来能跑」变成「其实没跑」。 |
| 「0% 成功率说明没用」 | 0% 恰恰证明回执是真的。一个能报 0% 且两次逐位一致的系统，才有可能诚实地报 73%。 |
| 「引擎自己就有 `--verify-determinism`」 | 引擎能自证，但**没有 cargo 的评审方**不能。`bridge.py verify` 让审计不需要装 Rust。 |
| 「换台机器就不一致了怎么办」 | 已经测了 Linux ↔ Windows 的完整回执，MATCH。不一致时的定位能力（精确到数组下标）也是产品的一部分。 |
